# 动态控制室首屏设计

## 目标

将首页顶部现有的静态工业图片主视觉升级为“工程控制流”动态首屏，让访客在进入页面的前几秒内看到从传感器、控制器到配料/装车的连续数据链路，同时保持工业官网的可信、克制和快速加载特性。

## 用户确认

用户已确认采用推荐方向：工程控制流。实现范围限定在首页首屏，不改变多语言路由、导航结构、后续内容区块和现有 SEO 元数据。

## 方案

首屏右侧视觉改为可访问的流程动画面板，包含背景网格、四个流程节点、连接线、数据脉冲、状态标签和一个简短的实时读数。动画分为两段：页面进入时由左到右完成一次入场，随后以 6 秒循环展示脉冲沿链路移动、节点状态切换和读数轻微变化。左侧标题、描述和 CTA 保持现有内容数据驱动结构。

动态视觉使用 HTML/SVG/CSS 和现有原生 `app.mjs`，不引入视频、Canvas、第三方库或外部资源。这样可以复用现有的三语言模板，保持首屏稳定高度，并避免视频加载、自动播放和版权素材问题。

## 组件边界

- `renderPage(locale)`：输出动态视觉的语义 HTML/SVG 结构；所有可见文案继续从 `content.mjs` 读取。
- `.hero-control-visual`：动态面板容器，负责背景、层级、裁剪和静态可读布局。
- `.flow-node`：单个流程节点，负责编号、标签、状态灯和响应式定位。
- `.flow-path` / `.flow-pulse`：流程连接线与移动数据脉冲；装饰元素通过 `aria-hidden="true"` 隔离，节点文本仍可被辅助技术读取。
- `app.mjs`：只负责在支持动画且未开启减少动态时添加运行状态；不使用定时器驱动业务数据，不改动现有滚动揭示逻辑。
- `mettler.css`：动态首屏的视觉语言、关键帧、桌面/移动端断点和减少动态降级。

## 动画行为

1. 首屏进入：面板淡入并轻微右移归位，流程节点按序淡入，路径由左向右显现。
2. 循环状态：数据脉冲沿 SVG 路径移动；当前节点高亮，状态标签保持低频呼吸效果；读数只做视觉上的轻微变化，不伪装成真实业务数据。
3. 悬停：桌面端悬停某个节点时，该节点提升对比度并显示对应流程标签；不改变页面布局。
4. 滚动：保留现有 IntersectionObserver，进入视口后才开始视觉动画，避免后台标签页持续消耗资源。
5. `prefers-reduced-motion: reduce`：显示完整静态流程图，移除循环、位移和呼吸效果；所有内容保持可读。
6. 移动端：节点改为两列/两行紧凑布局，脉冲仍可见但降低尺寸和动画幅度；不能遮挡图片替代文案、CTA 或导航。

## 可访问性与兼容性

- 面板使用 `role="img"` 与本地化 `aria-label` 概述，节点文本作为可见内容保留。
- 装饰网格、光晕和脉冲使用 `aria-hidden`，避免屏幕阅读器读取无意义字符。
- 不依赖 hover、音频或自动播放视频；键盘和触摸设备仍可访问所有 CTA。
- 浏览器不支持 SVG 动画时仍显示静态节点、路径和状态标签；不影响首页主要信息。

## 测试与验收

- 构建三种语言首页，确认 HTML 中存在四个流程节点、动态 SVG 路径和对应语言文案。
- 运行现有 Node 测试套件，确认多语言、SEO、资源路径和安全内容测试不回归。
- 用本地静态服务器检查桌面和移动宽度，确认首屏无水平溢出，导航和 CTA 可操作。
- 在 DevTools 中模拟 `prefers-reduced-motion: reduce`，确认动画停止且流程图仍完整显示。
- 检查首屏资源不新增外部域名请求，不引入第三方脚本或大体积视频。

## 不做的事情

- 本次不制作真实工厂视频，不新增后端实时数据接口。
- 本次不重构页面模板，不调整首页其余区块，不修改产品/案例数据。
- 面板中的读数是视觉占位，不向用户暗示接入了真实生产系统。
